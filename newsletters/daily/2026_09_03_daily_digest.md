<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">Cursor self-hosted machines — cloud agents run inside your own network</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">Cursor Cloud Agents can now do their tool calls on hardware you control, while the model still runs in Cursor's cloud.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
Self-hosted machines let a Cursor Cloud Agent execute commands on infrastructure you own instead of Cursor-managed sandboxes. There are two shapes: "My Machines" attaches one laptop or VM to a personal account, and "Team Pools" are named worker queues shared across an enterprise.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
Each worker holds an outbound HTTPS connection to Cursor — no inbound firewall hole needed. Pools scale on demand, growing as requests arrive and shrinking when workers disconnect. Workers on Linux and Mac also support computer use.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
Regulated teams have been blocked from cloud coding agents because hosted sandboxes mean code leaves the network. Running execution on your own machines removes that blocker while keeping the managed agent experience intact.
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
Platform and security teams in regulated industries who want to roll out coding agents without data leaving their network perimeter.
</p>

<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">Claude Code 2.1.259 — admins can push MCP servers to every user</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">The 2.1.259 release moves MCP configuration up to the administrator, and gives headless runs a way to refuse prompts instead of hanging.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
Claude Code 2.1.259 adds a <code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">managedMcpServers</code> setting so an organization can push HTTP and SSE MCP servers to all users from one place. It also introduces <code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">--permission-prompts none</code> for unattended headless hosts.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
MCP servers previously required each developer to configure their own. The new enterprise-scoped <code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">managedMcpServers</code> sits on top of local, project and user scopes — <code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">allowedMcpServers</code> was narrowed to filter only user-added servers. Headless session startup is also up to 50ms faster.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
Rolling an internal tool out to an engineering org is now a one-step admin action instead of a per-developer documentation exercise. On the CI side, headless jobs that hit an unexpected permission prompt used to hang — now they fail cleanly.
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
Platform and DevOps teams managing Claude Code across an organization, and developers running Claude Code in CI or automated pipelines.
</p>

<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">Astra's 'recurrent depth' — a reasoning loop that leaves no chain of thought</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">The Information says OpenAI's Astra loops its transformer layers to think, leaving fewer readable reasoning steps behind.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
Recurrent depth is the technique The Information reports OpenAI built into Astra, its unreleased frontier model. Instead of stacking more transformer layers, the model passes its hidden state through the same layers more than once before producing the next token — so part of the thinking happens inside the network rather than as written text.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
A looped transformer reuses one core set of layers repeatedly, raising effective depth without adding parameters. The trade-off is legibility: those extra passes produce no tokens, so there is no written record for a safety monitor to read. TechCrunch reports Astra's use of the technique is limited rather than unconstrained.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
Chain-of-thought text is the main tool safety teams use to catch a model misbehaving mid-task — it only works while the reasoning stays written down. Redwood Research CEO Buck Shlegeris warned that further recurrence could destroy chain-of-thought monitorability; OpenAI chief scientist Jakub Pachocki replied that the company "has worked to preserve and utilize chain-of-thought monitoring since our very first reasoning models."
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
AI safety and interpretability researchers, and anyone following how frontier labs balance capability with monitorability.
</p>

<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">Fable 5.1 Worlds — Claude agent swarms build explorable 3D neighbourhoods</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">Two explorable 3D reconstructions of real places, built end to end by Claude Fable 5.1 agent swarms.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
Fable 5.1 Worlds ships two browser-native 3D reconstructions of real places built with Three.js. Union Square in San Francisco has 453 buildings and 129 identified storefronts with walkable interiors; Higashiyama in Kyoto covers a 2.3 km route with 266 buildings and 1,938 trees rendered in an anime style.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
Autonomous Claude Fable 5.1 agents did the research, modelling and quality checks end to end, working from open data and reference imagery. The output is pure code — Three.js scenes you run locally with npm — not pre-built asset bundles.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
Holding a whole city block together is far longer than the single-file demos agent coding usually gets judged on. This repo is a concrete look at what a Claude Fable 5.1 swarm can finish without a person steering it — it drew 215 stars and hit the Hacker News front page within a day.
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
Graphics developers and agent researchers interested in what autonomous coding swarms can produce on complex, multi-file spatial tasks.
</p>
